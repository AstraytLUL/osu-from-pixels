# RL results: PPO fine-tuning of the BC osu! policy

Tables: `rl/results/tables.md`; figures: `rl/results/fig*.png`. Both are generated by
`python -m rl.report` from the raw evaluation files `rl/results/exp1.csv` and `exp2.csv`, plus
their `.offsets.jsonl` per-hit sidecars. Every number below comes from those files.

## Findings

1. **PPO from BC works where the policy already hits most objects.** PPO on a single map
   (Experiment 2, 1M steps, 3 seeds each) raised accuracy on all three maps with small seed spread:
   jump 95.0 → 98.9 ± 0.2 %, stream 88.7 → 95.9 ± 1.3 %, tech 86.3 → 91.5 ± 0.3 %. Curves were
   still rising at 1M steps.
2. **PPO fixed whichever error type the map is hard for.** On stream it cut click/timing circle
   misses (116 → 35); on jump it cut aim misses (28 → 3).
3. **Single-map PPO did not cost generality.** NoMod accuracy on the 19 held-out maps stayed at
   98.65–98.85 % (BC: 98.88 %).
4. **The same PPO barely moves under HD**, where BC misses ~80 % of objects (Experiment 1). Held-out
   HD accuracy went 17.0 → 22.0 ± 0.8 % in 2M steps (3 seeds). Supervised fine-tuning on HD
   re-renders (C) reached 83.6 %.
5. **HD breaks aim, not click timing.** Of B's ~337 circle misses per held-out map under HD, ~306
   are aim (position) misses; C removes them (1.5 left). Once the object fades, the BC policy loses
   track of where to go.
6. **Forgetting is the trade-off.** PPO on HD kept NoMod (98.35 ± 0.20 %). Supervised HD
   fine-tuning collapsed it (49.0 %), and training it 4× longer did not help (5 epochs: 46.8 %).
7. **The KL anchor to BC likely slowed Experiment 1 B.** All three seeds' curves bend upward in the
   last quarter, as its coefficient decays to 0 (Figure 1). This is a hypothesis; there is no run
   with the anchor turned off.
8. **Overall:** PPO fine-tunes a good policy reliably, but adapting to a large observation shift
   from sparse reward is beyond it at this budget.
9. **Additions D (seed 0) and C-mix (3 seeds).** PPO starting from C on HD + NoMod recovers NoMod
   only partly (49.0 → 56.4 %). Supervised fine-tuning on HD and NoMod data together (C-mix) keeps
   NoMod at 98.62 ± 0.15 % with 78.0 ± 1.8 % on HD, the best trade-off of all conditions.
10. **Transfer (addition):** single-map PPO policies also improve the other hard (8–9★) test maps:
    +1.9 to +4.1 pp on average, and up to +9.6 pp on the hardest jump maps for the jump
    specialist.

## Additions beyond the brief (user-approved)

These two conditions were added after Experiment 1's results. Their configs and code were committed
before training (commit 60e63c9). They are additions to the brief's design, and replace nothing
in it.

- **D: PPO starting from C, on HD and NoMod.** Each segment draws a (training map, HD or NoMod) pair
  uniformly; the KL anchor is C. All other settings as B (`rl/configs/exp1_D.yaml`).
  Question: can RL repair C's NoMod forgetting without losing HD? Findings 1 and 4 predict partial
  success: C at 49 % NoMod lies between B's 17 % (no progress) and Experiment 2's ~90 % (clear gains).
- **C-mix: supervised fine-tune on each training replay as recorded and with HD** (`rl/sft_hd.py --mix`,
  20 epochs, selected on the val maps with HD and NoMod). This is the cheap non-RL fix that D must
  beat.

Held-out maps (19); D: seed 0, C-mix: 3 seeds (rows D and C-mix in `rl/results/tables.md`):

| Condition | HD accuracy % | HD misses / map | NoMod accuracy % | NoMod misses / map |
|---|---|---|---|---|
| A: BC | 16.98 | 417.7 | 98.88 | 2.3 |
| C: supervised HD | 83.59 | 58.1 | 48.96 | 210.2 |
| D: C + PPO on HD and NoMod, 2M steps | **84.25** | 53.8 | 56.44 | 169.4 |
| C-mix: supervised HD and NoMod (3 seeds) | 78.00 ± 1.76 | 86.7 ± 11.1 | **98.62 ± 0.15** | 2.8 ± 0.3 |

- **D partly repairs forgetting and keeps HD.** NoMod went 49.0 → 56.4 %, still rising at 2M steps
  (Figure 4, `rl/results/fig4_exp1_D_curves.png`). HD went 83.6 → 84.3 %.
- **C-mix makes forgetting almost disappear:** NoMod 98.62 ± 0.15 %, 0.26 pp below BC, at a cost of
  ~5.6 pp of HD versus C (per seed: 79.7 / 78.0 / 76.2 %). So one network can play both mods well. C's collapse came from the data it was
  trained on, not from any lack of capacity.
- **Answer to D's question:** RL repairs forgetting, but slowly. The supervised fix that simply
  includes NoMod data beats D by 42 pp on NoMod and trails it by 6.3 pp on HD. This matches
  findings 1 and 4. At 49 % accuracy, misses still dominate the reward, so PPO improves slowly.
- D has one seed. Its 84.25 % on HD lies above all three C-mix seeds (best 79.7 %), and C started
  from the same checkpoint at 83.6 %. So D's HD advantage over C-mix is very probably real; it is
  inherited from C, not gained by PPO. HD-only supervised data gives higher HD accuracy at the cost
  of NoMod; mixed data trades ~6 pp of HD for keeping NoMod.

### Experiment 2 transfer (addition, eval only)

All nine single-map policies were evaluated on every 8–9★ test map except the Experiment 2
training maps themselves (`rl/maps.yaml` `exp2_transfer`, committed before evaluation;
`rl/results/exp2_transfer.csv`; Table 4 in `rl/results/tables.md`). That is 10 maps: 5 jump,
4 stream, 1 tech. NoMod; change vs BC in pp, mean ± sd over 3 seeds:

| Policy | jump maps (5) | stream maps (4) | tech map (1) | all 10 |
|---|---|---|---|---|
| A: BC (accuracy %) | 83.24 | 86.45 | 93.11 | 85.51 |
| jump specialist (4952940) | **+5.81 ± 0.89** | +2.40 ± 0.86 | +1.95 ± 0.56 | **+4.06 ± 0.60** |
| stream specialist (555797) | +1.29 ± 1.95 | +2.76 ± 2.31 | +1.29 ± 1.32 | +1.88 ± 1.86 |
| tech specialist (4377326) | +4.19 ± 0.93 | +2.11 ± 1.90 | +2.85 ± 0.43 | +3.22 ± 1.18 |

- **Training on one hard map improves hard maps the policy never trained on.**
  - Every specialist gains on average: +1.9 to +4.1 pp across the 10 maps.
  - Only 2 of 30 per-map means (map × specialist, averaged over seeds) are below BC, each by < 1 pp.
- **The largest gains are on the hardest maps.** On the three 9★ jump maps where BC is weakest
  (74.9 / 78.3 / 77.2 %), the jump specialist gains +9.6 / +6.9 / +5.9 pp.
  This bears directly on the project's question: part of BC's drop on hard maps can be recovered
  with RL on a single hard map, without demonstrations of those maps.
- **Style matters only partly.**
  - The jump specialist's gain on jump maps is more than twice its gain elsewhere.
  - The stream specialist transfers least and most variably.
  - The tech specialist transfers mostly to jump maps; 4377326 likely contains many jumps, though
    its style tag is "tech".
  - With 1 tech map and one training map per style, style-specific claims are weak.
- **Caveat:** two of the three Experiment 2 maps (4952940, 4377326) are 8★ *test-split* maps, by
  the brief's choice. The RL policies must therefore never be compared with BC's headline test
  results on those two maps. The transfer maps above exclude them.

### Experiment 2 control (addition, 15 Nov 2026)

Is the transfer gain specific to practising a *hard* map, or does the PPO recipe improve hard maps
whatever it trains on? `rl/run_control.sh` runs the Experiment 2 recipe unchanged
(`rl/configs/exp2_map.yaml`, 1M steps, seeds 0–2) on one map of the training range: 1570203, the
highest-rated jump map of the BC training split (6.32★), fixed by that rule before any control run.
The three policies are evaluated on the same 10 maps (`rl/results/exp2_control.csv`), on their own
map and on the held-out maps (`rl/results/exp2_control_own.csv`). NoMod; change vs BC in pp:

| Policy | jump maps (5) | stream maps (4) | tech map (1) | all 10 |
|---|---|---|---|---|
| control: PPO on 1570203 (3 seeds) | −1.74 ± 1.19 | −2.38 ± 1.95 | −1.93 ± 0.69 | **−2.02 ± 1.36** |
| sanity run: PPO on the train split, 300k steps (1 seed) | +1.12 | −1.53 | −0.12 | −0.07 |

- **The gain needs a hard map.** The control lowers accuracy on the 10 hard maps in all three seeds
  (−0.56 / −3.26 / −2.23 pp); the hard-map specialists gain +1.9 to +4.1 pp.
- The control still learns its own map: 99.72 % → 100.00 % in all three seeds. The held-out maps
  stay at 98.70 ± 0.20 % (BC 98.9 %), as for the specialists.
- The existing sanity run (`rl/runs/sanity_nm_seed0`: the whole train split, 300k steps) is a
  different recipe and a single seed; it neither helps nor hurts on average.
- One control map, of one style. The control shows that PPO as such does not produce the gain; it
  does not say how hard the training map must be.

## Deviations from the brief

1. **Click exploration is Gaussian noise on the press/held logits**, decoded by the BC click rule,
   instead of Bernoulli-sampled clicks. Sampling a click every frame would break the edge-triggered
   key decoder. Deterministic play is exactly BC (gate G2: 0.0000 pp parity).
2. **Noise level: aim 8 px, key logit 0.5.** This costs 1.1 pp versus deterministic play on 6
   training maps (`rl/runs/calibrate_grid*.json`). The brief allows up to ~2 pp; aim 12 px with key
   0.3 (1.9 pp) was rejected because it sits next to a cliff (aim 16 px costs 8.8 pp).
3. **Condition C is trained on NoMod + HR replays re-rendered with HD**, i.e. BC's own training data.
   HD changes only what is drawn, so the recorded actions remain valid labels.
4. **Condition C is the 20-epoch run.** The 5-epoch run was still improving at its last epoch; it is
   kept and reported as `exp1_C_5ep`: HD 71.2 %, NoMod 46.8 %.
5. **The BC policy was trained on NoMod + HR replays**, so "NoMod" rows evaluate a policy that has also
   seen HR. NoFail is implicit: maps are always played to the end.
6. **One base policy:** `runs/baseline_cap_seed0/best.pt` for every condition. Seeds vary PPO's
   randomness only, not the BC initialisation. Conditions A and C are single deterministic models
   (n = 1).

## Limitations

- **No hyperparameter search.** Every PPO run uses the brief's starting values; the sanity runs
  (the experiment log ~03:45) only checked that PPO neither breaks nor degrades BC. A tuned Experiment 1 B
  could do better, especially with a weaker KL anchor (finding 7).
- **Budgets are small:** 2M agent steps (~9 h of game time) for Experiment 1 and 1M for Experiment 2.
  Experiment 2's curves had not plateaued.
- **Training segments** are 15 s windows, started from Auto's state. The policy is never trained on
  recovering from its own earlier mistakes beyond a segment, though evaluation plays whole maps.
- **Experiment 2 uses one map per style**, so per-style conclusions rest on a single map each.
- **C and D have one seed each** (C-mix has three).
- **The reward** (300 → 1, miss → −1, slider ticks ±) is the brief's. Accuracy and misses are
  reported, not reward.

## Open questions

- Does Experiment 1 B improve markedly with the KL anchor off (or decayed faster)? Would a larger
  aim std find HD hits? The calibration rule caps it, but the cap was set on NoMod play.
- Would a curriculum work, i.e. PPO on gradually faster-fading objects? Addition D tests a related
  idea: starting PPO from C.
- Where does single-map PPO saturate? Would PPO on several hard maps at once transfer further than
  the single-map specialists (Table 4)?

## Reproduce

Run from the repository root with the project venv. Each line is one step:

```
python -m rl.gates parity; python -m rl.gates throughput; python -m rl.gates hd   # G1-G3 (the pre-run audit)
bash rl/run_sanity.sh                                               # condition A evals + sanity runs
python -m rl.sft_hd --seed 0 --epochs 20 --name exp1_C20            # condition C
python -m rl.evaluate --label exp1_C --checkpoint rl/runs/exp1_C20_seed0/best.pt --maps heldout --mods HD NM --out rl/results/exp1.csv
bash rl/run_experiments.sh                                          # Exp 1 B and Exp 2 B, all seeds, evals, report
python -m rl.ppo --config rl/configs/exp1_hd.yaml --seed 0          # one Exp 1 B run
python -m rl.ppo --config rl/configs/exp2_map.yaml --map 555797 --seed 0   # one Exp 2 B run
bash rl/run_additions.sh                                            # additions: D seed 0 and C-mix seed 0
python -m rl.sft_hd --seed 1 --epochs 20 --name exp1_Cmix --mix     # C-mix seeds 1, 2 (then rl.evaluate as above, label exp1_Cmix)
bash rl/run_transfer.sh                                             # Exp 2 transfer to the hard test maps
bash rl/run_control.sh                                              # Exp 2 control: PPO on a training-range map
python -m rl.report                                                 # tables + figures from the raw CSVs
```
